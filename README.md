# CyberShield

Одностраничный сайт-тест по цифровой безопасности: 30 вопросов, реестр опасностей, аккаунты с подтверждением почты, проверка нового устройства/IP и форум сообщества.

Проект состоит из двух частей:

| Часть | Что делает | Куда публиковать |
| --- | --- | --- |
| `index.html`, `css/`, `js/`, `config.js` | интерфейс сайта (чистый HTML/CSS/JS, без сборки) | **GitHub Pages** |
| `server/` | API: аккаунты, коды на почту, форум, реестр, админка, SQLite | любой Node-хостинг (Render, Railway, Fly.io, VPS) |

Фронтенд один и тот же, но работает в двух режимах:

* **серверный** — если по адресу `/api/health` отвечает backend. Тогда аккаунты, форум и реестр лежат в общей базе SQLite, а код подтверждения уходит **настоящим письмом**;
* **локальный (демо)** — если backend недоступен (GitHub Pages, открытие файла с диска). Всё хранится в `localStorage` браузера, код показывается на странице. Этот режим нужен, чтобы сайт не ломался без сервера.

## Структура

```
cybershield/
├─ index.html              разметка сайта (только HTML)
├─ config.js               адрес API (по умолчанию — автоопределение)
├─ css/styles.css          все стили
├─ js/
│  ├─ api.js               клиент API и определение режима
│  └─ app.js               логика приложения
├─ server/
│  ├─ package.json         без зависимостей, только node:http/node:sqlite
│  ├─ .env.example         переменные окружения
│  └─ src/
│     ├─ index.js          HTTP-сервер, роутер, раздача статики
│     ├─ db.js             схема SQLite, стартовые данные
│     ├─ auth.js           пароли (scrypt), токены, коды
│     └─ mail.js           отправка писем по SMTP (без библиотек)
└─ .github/workflows/pages.yml   автодеплой фронтенда на GitHub Pages
```

## Локальный запуск

```bash
cd server
node src/index.js
```

Откройте <http://localhost:3000> — фронтенд раздаётся тем же сервером, поэтому сайт сразу работает в серверном режиме: общая база и коды на почту.

Без настроенного SMTP код **не отправляется**, а печатается в консоль сервера и показывается на странице:

```
[mail] код для user@example.com: 481920
```

Администратор: `admin@cyber.ru` / `admin123`.

## Публикация фронтенда на GitHub Pages

1. Создайте репозиторий и загрузите проект:
   ```bash
   git init
   git add .
   git commit -m "CyberShield"
   git branch -M main
   git remote add origin https://github.com/ПОЛЬЗОВАТЕЛЬ/РЕПОЗИТОРИЙ.git
   git push -u origin main
   ```
2. В репозитории: **Settings → Pages → Build and deployment → Source = GitHub Actions**.
3. Готовый workflow `.github/workflows/pages.yml` сам соберёт и опубликует сайт при каждом пуше в `main`.
4. Сайт будет доступен по адресу `https://ПОЛЬЗОВАТЕЛЬ.github.io/РЕПОЗИТОРИЙ/`.

Без сервера сайт на Pages работает в демо-режиме: регистрация и форум живут в браузере посетителя, письма не отправляются.

## Подключение общей базы и настоящих писем

GitHub Pages — только статика, поэтому для аккаунтов и почты нужен отдельный Node-хостинг.

### 1. Развернуть `server/`

**Render** (бесплатный тариф):

1. New → Web Service → подключите репозиторий.
2. Root Directory: `server`.
3. Build Command: `echo no deps` (зависимостей нет).
4. Start Command: `node src/index.js`.
5. Environment — переменные из таблицы ниже.
6. Для постоянной базы добавьте диск (Render Disk) и укажите `DB_PATH=/var/data/cybershield.db`, иначе SQLite обнулится при перезапуске.

**Railway / Fly.io / VPS** — аналогично: команда `node src/index.js`, порт берётся из `PORT`.

### 2. Переменные окружения

| Переменная | Значение |
| --- | --- |
| `PORT` | порт (хостинг обычно задаёт сам) |
| `DB_PATH` | путь к файлу базы, например `/var/data/cybershield.db` |
| `SMTP_HOST` | `smtp.gmail.com` |
| `SMTP_PORT` | `465` |
| `SMTP_USER` | `telebot02@gmail.com` |
| `SMTP_PASS` | **пароль приложения Google** (16 символов) |
| `SMTP_FROM` | адрес отправителя (по умолчанию `SMTP_USER`) |
| `CORS_ORIGIN` | адрес сайта на Pages, например `https://ПОЛЬЗОВАТЕЛЬ.github.io` |
| `NODE_ENV` | `production` на хостинге |
| `ALLOW_DEV_CODE` | `0` в продакшене (иначе код придёт и в ответе API) |

#### Как получить пароль приложения Gmail для `telebot02@gmail.com`

1. Войдите в аккаунт Google → **Безопасность**.
2. Включите **двухэтапную аутентификацию** (без неё пароли приложений недоступны).
3. Откройте <https://myaccount.google.com/apppasswords>.
4. Создайте пароль для «Почта» → скопируйте 16 символов.
5. Вставьте их в `SMTP_PASS` (это не обычный пароль от почты).

Обычный пароль от Gmail в `SMTP_PASS` не подойдёт: Google отклонит вход.

### 3. Связать сайт с сервером

Откройте `config.js` и укажите адрес API:

```js
window.CYBERSHIELD_CONFIG = {
  apiBase: 'https://ваш-сервер.onrender.com',
  siteName: 'CyberShield'
};
```

Затем закоммитьте и запушьте — Pages пересоберётся автоматически. После этого на сайте в шапке будет «Сервер», в админке — настоящие участники, а коды подтверждения начнут приходить на почту.

Если `apiBase` оставить пустым, фронтенд попробует `/api` на своём же домене (это работает при локальном запуске через сервер).

## Как это устроено

* **Регистрация**: пароль → `scrypt` с солью; аккаунт создаётся неподтверждённым, на почту уходит 6-значный код на 10 минут. Вход возможен только после ввода кода.
* **Проверка устройства и IP**: при первом входе сервер запоминает отпечаток браузера и IP. Если при следующем входе они изменились — вход останавливается и на почту уходит новый код (5 попыток, повтор не чаще раза в 30 секунд). После подтверждения новые значения становятся доверенными.
* **Форум**: темы и ответы в общей базе; удалять может автор или администратор, закреплять и закрывать — только администратор.
* **Хранилище**: в серверном режиме данные в SQLite; в демо-режиме — через обёртку над `localStorage` с резервом в памяти и предупреждением на экране входа.

## Что менять

* **Вопросы теста** — массив `QUIZ_QUESTIONS` в `js/app.js` (у каждого вопроса есть `tip`).
* **Администратор** — константа `ADMIN` в `js/app.js` и запись `admin@cyber.ru` в `server/src/db.js` (там же стартовые темы форума и реестр опасностей).
* **Стартовый реестр** — массив `STARTER_THREATS` в `js/app.js` (демо-режим) и данные в `server/src/db.js` (серверный режим).
* **Стили** — `css/styles.css`, переменные в блоке `:root`.

## Ограничения

* GitHub Pages не выполняет серверный код: без развёрнутого `server/` аккаунты и форум остаются локальными для каждого посетителя.
* Файл базы SQLite — один на сервер. Для нескольких экземпляров приложения нужна внешняя СУБД (PostgreSQL).
* Отправка письма требует рабочего SMTP; при ошибке отправки сервер вернёт понятную ошибку, а в dev-режиме код всё равно появится в консоли.
